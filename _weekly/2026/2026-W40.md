## GEMC

- Ported optimized LTCC CAD geometry from the Meson branch, with a reproducible comparison benchmark.
- Measured full LTCC CAD loading, memory, electron/hadron transport, and geometry warnings.
- Fixed the intermittent boolean_solids failure: the uniform generator vertex could spawn outside the
  too-small world and crash Geant4 navigation; widened the world to contain the full spread.
- Silenced the nodiscard std::stod warnings in the CAD and SQLite geometry loaders.
- Raised the project C++ standard to C++20 and stripped Geant4's hardcoded -std=c++17 pkg-config flag so it
  governs every translation unit, matching ROOT's C++20 build and removing the standard-mismatch warning.
- Adopted C++20 starts_with/ends_with, container contains(), and std::numbers::pi in place of the
  rfind/compare idioms, find-against-end membership tests, and the non-standard M_PI macro.

## GEMC3

- **MILESTONE: clas12-systems now installs from scratch with no pre-existing GEMC — it compiles GEMC from the
  gemc subproject onto a bare Geant4 (g4install) environment, and the Test CI workflow proves it across every
  supported distro.**
- Diagnosed the PCAL compare_all_edep failure as gemc3 keeping FADC-threshold-rejected ECAL hits in the true
  bank while GEMC2 drops them; made intrinsic threshold/efficiency rejection also drop the true-info row to
  match GEMC2.
- Added a GEMC subproject fallback and a use-gemc-location option so clas12-systems builds GEMC from source
  when no install is found, keeping Geant4 external and never autobuilt.
- Made the GEMC subproject dependency propagate yaml-cpp so plugins resolve the public goption.h include that
  an installed GEMC supplies via its headers.
- Made generate_geometry.zsh default to the build-tree pygemc venv so detector scripts find pygemc and
  clas12_common without a hand-set interpreter.
- Gated GEMC's own tests and examples behind a standalone-build check so they no longer pollute
  clas12-systems meson test when GEMC is built as a subproject.
- Pointed the SRO full-path test at the installed GEMC when GEMC is built from source, since the subproject
  build-tree binary cannot resolve its runtime layout.
- Changed SRO plugin linkage to reuse runtime framework symbols and avoid Linux static TLS exhaustion.
- Isolated bundled XML parser symbols to fix static linking; verified mesh imports and simulation.
- Fixed SRO example linking with strict symbol checks; verified crate output across worker counts.
- Removed special GEMC data-library linking from CLAS12 plugins and verified release plugin loading.
- Fixed CLAS12 profiling builds to resolve shared GEMC libraries while preserving static release linking.
- Moved Meson native-file settings into project defaults and verified CI overrides and a fresh build.
- Documented the meson dependency-loading logic for CLHEP, Qt6, and Geant4 in new READMEs under both meson
  directories, explaining the producer/consumer split and why CLHEP stays shared in the core but static in
  the plugins.
- Split thread-scaling scenarios into independent matrix jobs with separate reports and a shared build; moved
  thread-scaling builds and runs to Ubuntu 26.04 Geant4 images with explicit dependencies.
- Standardized CI environment logs with CPU, Docker, Geant4, and physics-data details.
- SRO presentation to the EPSCI/SRO meeting; SRO channel added to Team SciComp.
